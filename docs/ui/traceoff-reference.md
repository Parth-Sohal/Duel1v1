# Traceoff Export: What It Contains and What We Reuse

Source: the Google AI Studio export "Traceoff — 1v1 Coding Duel Arena" (internal name "{ duel }"). Files received: `index.html`, `metadata.json`, `package.json`, `README.md`, `server.ts`, `tsconfig.json`, `vite.config.ts`, `.gitignore`, `.env.example`, `bun.lock`. **Not received:** the `src/` folder (screens, styles, types).

## 1. What the prototype is

A 1v1 "code-reading" game: a bug is planted in a piece of code and two players race to find it. Around it: a spectator gallery with voting, crowd-chosen match modifiers, and a referee AI called KERN that explains how you read the code.

Our product is different: players **write** code and win by passing tests. We use the prototype for **look, vocabulary, and feature ideas**, not for the game rules.

| Data | Fields | Where we could use it |

## 5. What we do not reuse, and why

| Item | Reason |
|---|---|
| In-memory rooms and votes | Lost on restart; our design keeps match state in PostgreSQL |
| No login on `/api/kern/*` | Anyone could run up the AI bill; we require login and a per-user daily cap |
| Client-sent `arena:event` text | Any browser can post any actor and text; our feed is generated by the server only |
| Unlimited crowd votes | Needs per-user limits |
| Fake counters and hardcoded names (1,284 live duels, 18,402 bugs, NIPUN, AMAN) | Show real numbers only |
| Single `server.ts` with game state | Our game server is the referee, with timers, winners, and points |
| Hardcoded Gemini model name | Make it a config value and check it works with the key in use |
